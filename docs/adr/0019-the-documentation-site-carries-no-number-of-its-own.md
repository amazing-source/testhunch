# 19. The documentation site carries no number of its own

Date: 2026-09-15
Status: accepted

## Context

README.md is about 400 lines doing three jobs: the pitch, the measurement report, and the reference
for the CLI, the Action, six test runners, the API and the store. A reader who wants to know whether
`--budget` counts tests or time reads the same page as a reader deciding whether to try the project
at all, and neither is served well.

An audit on 2026-09-15 found six defects in the published prose, and every one of them had the same
shape: a sentence written by hand beside a number produced by a command, left behind when the
command ran again. The worst said a real regression was "missed at every budget" when the generated
page it linked to said it was caught at 25% and 50%. The same day, a worse instance of the same
shape turned up outside the prose: the front page measured a ranking that PyPI did not carry, and
told the reader to install the version its own tables used as the baseline to beat (0.3.0 fixed it).

A documentation site multiplies pages. Multiplying this failure mode by the number of pages is the
risk worth deciding about before writing any of them, not after.

## Decision

**The site carries no measured number of its own.** Methodology pages say how a thing is measured
and link to `benchmarks/results/`, which stays in the repository, generated by
`python -m benchmarks.rtptorrent` and `python -m benchmarks.study`. A number lives in exactly one
file, and that file is written by the command that computed it. Where a page would be poorer without
a figure, it links to the row rather than repeating it.

This is what keeps the choice of engine cheap to reverse, so the engine is decided second.

**The engine is Mintlify**, under its open-source programme: a recognised OSS licence, not
venture-backed, not company-owned — testhunch is Apache-2.0 and has no company behind it. Three
reasons specific to this project, beyond it looking good, which for a pre-alpha tool nobody has
heard of is not nothing:

- **No second toolchain.** The repository is uv, ruff, mypy and pytest. Docusaurus or Starlight add
  Node, an npm lockfile, a build step in CI, and a class of failure — a transitive dependency
  breaking a docs build — with nothing to do with the product. Mintlify takes MDX and a `docs.json`
  and builds it elsewhere.
- **Versioning is first-party**, a `versions` array in `docs.json`. "Which version does this page
  describe" is this project's demonstrated failure mode, so a versioning mechanism that is
  configuration rather than a third-party plugin is worth more here than it would be elsewhere.
- **The API playground is first-party.** The API is FastAPI, so an OpenAPI schema falls out for
  free, and Phase 5 is the hosted service: that is when an interactive playground stops being
  decoration.

**The fallback is named in advance: Astro Starlight**, self-hosted on GitHub Pages, if the
programme is refused or ends. The content is written to make that a weekend rather than a rewrite:
plain Markdown, the fewest proprietary components that will do the job, no numbers to re-verify
because there are none to re-verify.

**The prose stays French and the generated pages stay English**, as the project already works. The
site is bilingual by construction; translating the generated pages would mean writing their figures
a second time, which is the thing this ADR exists to prevent.

## Consequences

- README.md keeps the pitch, the comparison with the alternatives, a short quickstart and the
  headline result with a link. Everything else moves to the site, which becomes the reference.
- The site depends on a service we do not run. What that service holds is prose; every figure and
  every ADR stays in git, readable without it. If the site disappears tomorrow, nothing that proves
  an accuracy claim disappears with it.
- A page that wants a number gets a link instead, which is worse to read and better to trust. That
  trade is made deliberately and will feel wrong at least once.
- Mintlify's open-source programme states no terms for revocation. "Free forever" with nothing
  written about ending is a promise to read in both directions, and the reason the fallback is
  named here rather than improvised later.
